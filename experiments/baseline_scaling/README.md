# 第 1 步：独立采样基线 X%

模型 `psaegert/flash-ansr-v25.0-T8-3M`，不做任何改动，只做独立采样：调用 `fit(draws=N)`，候选排序用 `ranking="mdl"`。

## 设置（后续 04 的所有实验都沿用）

| 项目 | 取值 |
|---|---|
| 评测集 | srbf `fastsrb`，共 120 题，数据 seed 20260825；每题 512 个拟合点、512 个留出点，无噪声 |
| N | 每题的采样次数 `draws`，取 50 / 100 / 300 / 1000 / 3000 |
| fit seed | 每个 N 只跑 1 次（seed 0），与项目的 srbf 评测一致；设备 CPU（MPS 不支持 float64，而模型的 64 位 IEEE754 输入编码需要它） |
| 解出判据 | 在**留出点**上 FVU ≤ float32 eps，方差按 float64 计算，即 `srbf.metrics.is_perfect_fit` |
| **X%** | N = 1000 时的 **oracle** 解出率 |

### 两种解出率
- **oracle**：常数拟合完成后，候选池中**任意一个**候选在留出点上达标，就算解出。它衡量"对的公式有没有被生成出来"，精修改进的正是这一项。
- **top-1**：只有排序后的第一名在留出点上达标才算解出，衡量的是实际交出去的答案。
- oracle 明显高于 top-1 时，说明瓶颈在挑选，而不在生成。

### 计算量（主口径固定为 FLOPs）
每题的计算量：

    C = Σ_draws  L_seq · F_tok(L_ctx)  +  2 · P_enc · n_support
    F_tok(L) = 2 · P_dec + n_layers · 4 · d · (L + S_mem)

- `L_seq`：一次采样经过的解码位置数，等于前缀加生成部分的非 pad token 数。基线没有前缀，只有 3 个 token 的提示。
- `P_dec` / `P_enc`：解码器和编码器的参数量；`d` 为 192，`S_mem` 是编码器 seed 数（128）。
- 重复的采样也计入计算量，因为它们确实算过了。由于去重后的 token 序列不再保留，总 token 数按 `draws × 唯一采样的平均长度` 估计。
- 精修阶段每个样本还要加上前缀（候选表达式）的长度，cross-attention 的记忆也会增加到 (K+1)·S_mem，两者都代入同一个公式。这样精修和基线就能**在相同 C 下**比较，而不是在相同 N 下比较。
- 辅助口径一并记录：`draws`、`gen_tokens_est`，以及墙钟时间 `generation_time` / `refinement_time`。墙钟时间受硬件影响，只作参考。

## 结论
全量结果：120 题，每个 N 跑 1 次（seed 0），无报错。

| N | oracle 解出率 | top-1 解出率 | 95% 区间 | 不同公式数 | FLOPs/题 | 耗时/题 |
|---|---|---|---|---|---|---|
| 50 | 28.3% | 28.3% | 21–37% | 42 | 9.1e9 | 1.8 s |
| 100 | 30.0% | 28.3% | 23–39% | 84 | 1.7e10 | 2.9 s |
| 300 | 40.0% | 40.0% | 32–49% | 251 | 4.7e10 | 8.4 s |
| **1000** | **46.7%** | **46.7%** | 38–56% | 838 | 1.5e11 | 27 s |
| 3000 | 50.0% | 50.0% | 41–59% | 2506 | 4.5e11 | 155 s |

**X% = 46.7%**（56/120）。

相邻 N 之间的配对比较（McNemar 检验）：

| 区间 | 新增解出 | 丢失 | p 值 |
|---|---|---|---|
| 50 → 100 | 8 | 6 | 0.79 |
| 100 → 300 | 12 | 0 | <0.001 |
| 300 → 1000 | 8 | 0 | 0.008 |
| 1000 → 3000 | 4 | 0 | 0.13 |

各次运行是独立采样，不是嵌套的，所以 N 变大时也可能"丢失"题目。

题目三分类（看 seed 0 第一次解出时的 N）：N ≤ 100 就解出的 42 题；N 更大才解出的 18 题；到 N=3000 仍未解出的 60 题。

**解读**
1. **收益在递减，但还没有完全变平。** N 每乘约 3 倍，新增解出的题数依次是 12、8、4。1000 → 3000 只多解出 4 题（+3.3 个百分点），而 FLOPs 和耗时都翻了 3 倍（耗时多 5.8 倍），这一步已经不显著（p=0.13）。这支持 03 的"饱和"假设，但证据还不算强。
2. **oracle 和 top-1 基本相同**（只有 N=100 时差 1 题）。只要对的公式生成出来了，MDL 排序几乎总能把它挑中。所以瓶颈在**生成**，不在挑选，这正是精修要解决的问题。
3. **有一半的题（60/120）到 N=3000 都没解出。** 精修有机会，前提是这些题的候选里有"接近对"的公式；如果模型的分布根本没覆盖到真公式，精修可能也救不了。这 60 题在 N=3000 时最好候选的留出 FVU 分布如下：< 1e-4 的有 10 题，< 1e-2 的有 18 题，< 0.1 的有 26 题，其余 34 题 ≥ 0.1，差得很远。也就是说，约 18 题差一点就对了（最该精修），另外约一半的未解出题可能需要模型"走出"原有分布。
4. **重复采样不多。** N=3000 时仍有 84% 的采样是不同的公式，可见"饱和"主要不是因为重复，而是新采到的公式大多仍然不对。
