# Good Report：写一轮实验的分析报告

报告是一条**证据链**：发现的问题 → 想回答的问题 → 怎么比 → 结果（数字）→ 原因 → 结论 → 下一步。读者顺着任何一行往下读，都能看到"为什么问、看到了什么、所以是什么"。

骨架和示范行见 [TEMPLATE.md](TEMPLATE.md)，动笔前先读它。

## 步骤

### 1. 收集材料

读这些，把要用的数字连同出处记下来：

- 这一轮的配置：`experiments/<name>/<round>/config.yaml`
- 开跑前定的规则：实验规则文件里这一轮的那一节。开跑前锁定的判断标准，逐条抄下来。
- 运行产物：`runs/<name>/<round>/`，包括自动生成的表格、json、训练日志。
- 上一轮的报告：这一轮要解决的问题从这里来。

**完成标准**：每个验证性分析（含判断标准）、次要分析、探索性分析，都找到了数字和产物文件。缺数字的项写进"局限"，不要编。

### 2. 先写总表，再写细节

按 TEMPLATE.md 的顺序写。总表是报告的主干，细节节只放总表引用到的证据。

### 3. 自查并删减

逐条检查，不合格就改，改完再查一遍：

- [ ] 每个问题都有三个标签，各管一件事，不要混用：
  - **分析类型**：验证性 / 次要 / 探索性（定义见 TEMPLATE.md §2）。
  - **是否达标**：✅ 达到 / ❌ 没达到 / ➖ 分辨不出（区间跨过 0）。没有判断标准的问题写"—"。
  - **证据强度**：已证实 / ❓ 推测。
- [ ] 绿勾 ✅ 只表示"达到"。标准没达到的问题，是否达标必须是 ❌ 或 ➖。
- [ ] 总表只放短格子（问题、结论、三个标签）；怎么比、结果、原因写在每个问题的卡片里。
- [ ] 每个"已证实"都附了数字。比较类结论还要附题目数和 95% 区间。
- [ ] 每个 ❓ 都写了"怎么验证"，并且在"下一步"里有对应的实验，或者在"局限"里说明为什么暂时不验证。
- [ ] 样本小、只能看出方向的结果，证据强度标 ❓，不标"已证实"。
- [ ] 区间跨过 0 的，写"分辨不出差别"，不写"一样"。
- [ ] **说一次**：同一个结论只在一个地方展开。其他地方只写"见 §N"。重点查三处：问题卡片和判断标准表、卡片的"原因"和细节节、"原因分析"和卡片。
- [ ] 每个数字都能在第 1 步记下的产物文件里找到。
- [ ] 字数：`LC_ALL=en_US.UTF-8 wc -m <报告>` 不超过 6000 字（第 3 轮报告原来是 11500 字）。超了就先删重复，再删不影响结论的过程描述（比如运行时遇到的小故障）。用户要求详细版时可以超。

### 4. 交付

告诉用户三件事：报告路径、字数、哪些结论还是 ❓（各自用哪个实验验证）。

## 写法

- 用中文，用大白话。代码、文件名、命令、指标名保持原样。
- 每节第一句就是这一节的结论，后面跟一张表。表后最多 3 条说明，只写表里看不出来的东西。
- 关键发现配一个打比方。例如"拿着标准答案抄作业，只抄对四分之三的字：说明他只是参考了答案，并没有照抄"。整篇一到两个就够。
- 术语第一次出现时用一句话解释。这个实验的 README 或规则文件里已经定义过的术语，链接过去就行，不要重新解释。
- 统一用标准术语：验证性分析、次要分析、探索性分析；验证集、开发集、测试集。不用自己起的口语叫法。
- 报告是手写文件，生成后不再让脚本覆盖。自动生成的表格留在 `runs/`，在报告里链接过去。
